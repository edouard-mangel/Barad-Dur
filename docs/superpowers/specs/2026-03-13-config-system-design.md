# Design: `.ncrunch/barad-dur.toml` Configuration System

## Context

Barad-dur currently requires all settings via CLI flags. Repos that consistently need `--exclude '*.resx' --exclude '**/i18n/**' --since 3months` must repeat these flags every run. A per-repo config file eliminates this friction and makes settings discoverable.

## Scope

- New file: `src/config.rs` — config struct, loading, merge logic, validation
- New subcommand: `barad-dur init` — generates `.ncrunch/barad-dur.toml` with smart defaults
- Modified: `src/cli.rs` — add `init` subcommand, wire config into `AnalyzeArgs`
- Modified: `src/main.rs` — load config before analysis, merge with CLI flags

- Modified: `src/scorer.rs` — accept weights from config instead of hardcoded `WEIGHTS` const
- Modified: metric modules — accept threshold parameters from config where applicable

Note: weights and thresholds require refactoring the scorer and metrics modules to accept configurable values instead of hardcoded constants. This is a larger change surface but necessary for the config to be meaningful.

## Section 1: Config File Format

TOML format. File lives inside the `.ncrunch/` directory at the **git workdir root** (where `.git/` lives), as `.ncrunch/barad-dur.toml`. This keeps all barad-dur artifacts in one place alongside the blame cache (`blame_cache.bin`) and history (`history.json`). When the user runs `barad-dur analyze src/`, the config is still loaded from the repo root's `.ncrunch/`, not from `src/`.

```toml
# .ncrunch/barad-dur.toml — Barad-dur repository configuration
# All barad-dur files live in .ncrunch/ (config, blame cache, history).
# Generated by `barad-dur init`. Edit freely.
# CLI flags override these values when explicitly passed.

# ──────────────────────────────────────────────────
# Analysis scope
# ──────────────────────────────────────────────────
[analysis]

# How far back to look at git history.
# Accepts: "3months", "6months", "1year", "30days", or an ISO date "2024-01-01".
# Default: "6months" — a good balance between recency and trend visibility.
since = "6months"

# Skip the git-blame phase entirely.
# Blame is the slowest step but powers bus-factor, ownership, and code-age metrics.
# Set to true for quick iteration; false for full analysis.
# Default: false
skip_blame = false

# ──────────────────────────────────────────────────
# File exclusions
# ──────────────────────────────────────────────────
[exclude]

# Use the built-in list of translation/resource file extensions?
# Built-ins: *.resx, *.po, *.pot, *.xlf, *.xliff, *.strings, *.arb, *.lproj
# These files change together by definition and inflate coupling/churn metrics.
# Default: true
use_defaults = true

# Additional glob patterns to exclude from ALL analysis phases.
# Each pattern is matched against the file's repo-relative path.
# Examples:
#   "*.generated.cs"       — any generated C# file
#   "**/i18n/**"           — anything under an i18n directory
#   "vendor/**"            — vendored third-party code
#   "**/*.min.js"          — minified JavaScript
patterns = []

# ──────────────────────────────────────────────────
# Category weights (must sum to 100)
# ──────────────────────────────────────────────────
[weights]

# How much each category contributes to the overall score.
# Increase a weight to make that category matter more in the final grade.
# All four values must add up to exactly 100.
health    = 30   # Bus factor, churn hotspots, coupling, staleness, complexity
team      = 30   # Knowledge distribution, contributor activity, ownership, silos
evolution = 20   # Growth trend, refactoring ratio, code age, commit cadence
hygiene   = 20   # Commit messages, history cleanliness, gitignore coverage

# ──────────────────────────────────────────────────
# Scoring thresholds — tune what counts as "good" or "bad"
# ──────────────────────────────────────────────────

[thresholds.health]
max_complexity       = 20    # Cyclomatic complexity above this is flagged
hotspot_top_n        = 10    # Number of worst hotspots to surface
coupling_min_commits = 5     # Minimum co-changes before coupling is flagged
bus_factor_warning   = 2     # Bus factor at or below this triggers a warning

[thresholds.team]
silo_max_owners      = 1     # Files with this many owners (or fewer) are "siloed"
activity_window_days = 30    # Recent window for contributor activity scoring

[thresholds.evolution]
growth_baseline_months = 3   # Baseline period for growth trend comparison
refactor_ratio_target  = 0.1 # Target: 10% of changes should be refactoring

[thresholds.hygiene]
min_message_length = 10      # Commit messages shorter than this are penalized
max_message_length = 72      # Subject lines longer than this are penalized

# ──────────────────────────────────────────────────
# Output preferences
# ──────────────────────────────────────────────────
[output]

# Default output format when no --json or --html flag is passed.
# Options: "cli", "html", "json"
# Default: "cli"
format = "cli"

# Automatically open HTML reports in the browser after generation.
# Only applies when format = "html" or --html is passed.
# Default: false
auto_open = false
```

## Section 2: Config Loading & Merge Logic

### 3-Layer Merge

```
Hardcoded defaults  →  .ncrunch/barad-dur.toml  →  CLI flags
   (lowest)              (middle)           (highest)
```

### `RepoConfig` struct (`src/config.rs`)

```rust
pub struct RepoConfig {
    pub since: Option<String>,
    pub skip_blame: bool,
    pub exclude_use_defaults: bool,
    pub exclude_patterns: Vec<String>,
    pub weights: CategoryWeights,
    pub thresholds: Thresholds,
    pub output_format: OutputFormat,  // cli | html | json
    pub auto_open: bool,
}
```

With `Default` impl providing the hardcoded defaults (same values as current behavior).

### Loading

```rust
pub fn load(repo_root: &Path) -> Result<RepoConfig>
```

1. Start with `RepoConfig::default()`
2. Look for `.ncrunch/barad-dur.toml` in `repo_root`
3. If found, parse with `toml` crate, overlay non-default values
4. Return merged config

### CLI Override

In `main.rs`, after loading config and parsing CLI args:

```rust
let config = config::load(&local_path)?;
let merged = config::merge_with_cli(config, &args);
```

**Detecting explicit CLI flags:** CLI boolean fields that participate in config merge (`skip_blame`, `no_default_excludes`) are changed from `bool` to `Option<bool>` in `AnalyzeArgs`, with no clap default. `None` means "user didn't pass it" (TOML value wins), `Some(true)` means "user explicitly set it" (CLI wins). This is the idiomatic clap-derive approach — no need for `ArgMatches::value_source()`.

Fields that are already `Option<String>` (`since`, `until`) or `Vec<String>` (`exclude`) work naturally: `None`/empty means "not passed".

**Special merge rules:**
- `--exclude` patterns **append** to TOML patterns (no deduplication — overlaps are harmless)
- `--no-default-excludes` on CLI **overrides** `use_defaults = true` in TOML
- `--since`/`--until` on CLI **replace** TOML values entirely
- `--all` on CLI **replaces** any TOML time window

**Config load ordering:** Config is loaded **after** `local_path` is resolved (since the config file lives at repo root and we need to know the path first, especially for URL clones), but **before** `build_time_window` and `Collector::open`.

### Validation

After merge, validate:
- Weights sum to 100
- Thresholds are non-negative
- `since` parses as a valid time spec

Print specific error messages on validation failure, exit code 1.

## Section 3: `barad-dur init` — Smart Scaffold

Default mode (no `-i` flag). Scans the repo and generates a commented `.ncrunch/barad-dur.toml`.

### Detection heuristics

| Signal | How detected | Config effect |
|--------|-------------|---------------|
| Translation files | Walk HEAD tree for `.resx`, `.po`, `.pot`, `.xlf`, etc. | Add to `exclude.patterns` |
| Generated code | Look for `*.generated.*`, `*.designer.*`, `*.g.cs` | Add to `exclude.patterns` |
| Vendored deps | Check for `vendor/`, `third_party/`, `node_modules/` in tree | Add to `exclude.patterns` |
| i18n directories | Directories named `i18n`, `l10n`, `locales`, `translations` | Add `**/dirname/**` pattern |
| Team size | Count distinct authors in last 6 months | Comment hint in weights section |
| Repo scale | File count, commit count | Suggest `skip_blame` if >10k files |

### Output

Generates `.ncrunch/barad-dur.toml` with:
- Detected patterns as uncommented values
- Explanatory comments noting what was detected ("# Detected 16 .resx files")
- Undetected sections left at defaults with comments

### Guard

If `.ncrunch/barad-dur.toml` exists: error with "Config already exists. Use `--force` to overwrite."

## Section 4: `barad-dur init --interactive` — Guided Wizard

### Mode Selection (first question)

```
$ barad-dur init -i

  barad-dur config wizard
  ───────────────────────

  Scanning repository...

  ? Configuration mode:
    [S] Simple — 3 quick questions, smart defaults for everything else
    [A] Advanced — walk through all settings with detected recommendations
    Choice [S]: ▌
```

### Simple Mode (3 questions max)

```
  ① Time window
     Detected: 847 commits over 14 months
     ? Analysis window [6months]: ▌

  ② Exclusions
     Detected 16 .resx files, 4 files under i18n/
     ? Exclude these from analysis? [Y/n]: ▌

  ③ Output
     ? Default output format (cli/html/json) [cli]: ▌

  Writing .ncrunch/barad-dur.toml... done
```

All other settings (weights, thresholds, skip_blame) use smart-detected defaults silently.

### Advanced Mode (5 groups)

```
  ① Time window
     Detected: 847 commits over 14 months
     Recommended: 6months (default)
     ? Analysis window [6months]: ▌

  ② Exclusion patterns
     Detected 16 .resx files, 4 i18n .ts files
     Recommended excludes:
       - *.resx (16 files)
       - **/i18n/** (4 files)
     ? Add these exclusions? [Y/n]: ▌
     ? Additional glob patterns (comma-separated, empty to skip): ▌

  ③ Category weights
     Default: health=30, team=30, evolution=20, hygiene=20
     ? Adjust weights? [y/N]: ▌

  ④ Thresholds
     Detected: 12 authors, avg complexity 8.2
     ? Max healthy complexity [20]: ▌
     ? Bus factor warning threshold [2]: ▌
     ? Skip remaining thresholds (use defaults)? [Y/n]: ▌

  ⑤ Output preferences
     ? Default output format (cli/html/json) [cli]: ▌
     ? Auto-open HTML reports? [y/N]: ▌

  Writing .ncrunch/barad-dur.toml... done
```

### Behaviors

- **Defaults pre-filled** from smart scan, shown in `[brackets]`
- **Enter accepts default** — speed through by pressing Enter
- **Non-TTY fallback**: if stdin is not a terminal, falls back to non-interactive scaffold with a warning
- **Same output**: produces identical `.ncrunch/barad-dur.toml` as non-interactive mode, just with user-confirmed values

### Implementation

Uses `std::io::stdin().read_line()` with a small `prompt(question, default) -> String` helper. No extra dependencies.

## Section 5: Error Handling

### Config file errors

| Error | Behavior |
|-------|----------|
| Bad TOML syntax | Print line/column from parser, exit 1 |
| Unknown keys | Warn but continue (forward compat). Implementation: two-pass parse — first deserialize to `toml::Value` to detect unknown keys, then deserialize to the config struct. |
| Invalid values (e.g. weights != 100) | Print specific message, exit 1 |

### `barad-dur init` errors

| Error | Behavior |
|-------|----------|
| File exists | Error: "Config already exists. Use `--force` to overwrite." |
| Not a git repo | Error: "`barad-dur init` must be run inside a git repository." |
| No write permission | OS error bubbles up |

## Dependencies

- Add `toml = "0.8"` to `Cargo.toml` for config parsing
- No other new dependencies (stdin prompts use stdlib)

## Performance

Config loading is a single file read + TOML parse — sub-millisecond. No impact on analysis performance.
