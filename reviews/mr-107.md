# MR !107 — Coupling scoring determinism

## Finding 1 — High — Static resolver capability still turns broken resolvers into perfect scores

`src/metrics/coupling/mod.rs` (`has_import_extractable_files`) treats the presence of both an import query and a resolver dispatch arm as proof that an empty import graph was measured successfully. That is not sufficient: the Go resolver produces a literal `*.go` candidate and the C# resolver maps namespaces as if they were filenames, so both can extract imports while resolving zero edges. Their empty graphs therefore receive clean coupling scores.

This is the same false-perfect condition the MR is intended to eliminate for unsupported languages. Track actual extracted/resolved counts (or resolver confidence) rather than static dispatch membership. MR !122 attempts this follow-up, though its own review notes a remaining ambiguity.
