# MR !118 — PHP language support

## Finding 1 — High — Valid PSR-4 array mappings are discarded

`src/collector/composer.rs:38` calls `target.as_str()?`, so it only accepts a single directory string. Composer permits a PSR-4 namespace prefix to map to an array of directories. Every valid array-valued mapping is silently skipped, causing imports under those namespaces to disappear from the graph.

Accept both string and array values and emit one `Psr4Root` per string directory. Resolution must try all directories for the longest matching namespace prefix rather than selecting only one root.

## Finding 2 — Medium — Extensionless include paths are misclassified as namespaces

`src/collector/import_resolver.rs:230` classifies any PHP specifier without a dot as a namespace. A path such as `require __DIR__ . '/bootstrap/autoload'` contains neither a backslash nor a dot and is sent to PSR-4 resolution rather than being resolved relative to the requiring file.

Preserve the extraction kind (`use` versus `require/include`) in the raw import record instead of inferring it from string punctuation.
