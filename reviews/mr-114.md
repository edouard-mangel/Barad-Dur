# MR !114 — Kotlin import resolution

## Finding 1 — Medium — Common Kotlin wildcard imports never resolve

`src/collector/import_resolver.rs:205` converts the full specifier and its immediate parent into filename candidates. For `import com.foo.*`, those candidates become `com/foo/*.kt` and `com/foo.kt`; neither can match the files actually exported by the package. Wildcard imports are a normal Kotlin construct, so repositories using them silently lose all corresponding graph edges.

Handle a trailing `.*` as a package import and resolve it against files/types in that package, with an explicit policy for the multiple edges it can produce.

## Finding 2 — Medium — Conventional test and Android source roots are omitted

`resolve_kotlin_import` only tries the repository-relative package path and `src/main/kotlin`. It misses `src/test/kotlin`, `src/androidTest/kotlin`, Android build-variant roots, and module-prefixed roots such as `app/src/main/kotlin`. A typical multi-module Gradle/Android repository can therefore extract imports but resolve few or none of them.

Derive Kotlin source roots from the source file/module layout (or Gradle metadata) instead of hard-coding a single root.
