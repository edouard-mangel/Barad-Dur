# MR !116 — Registry timeout test

## Finding 1 — Low — The test no longer verifies the supplied timeout value

`src/registry/client.rs` accepts any elapsed time below the 30-second default as proof that a requested 200 ms timeout was applied. A regression that turns the argument into 10 or 29 seconds still passes. It also lets the test occupy a runner for almost 30 seconds before failing.

Use a generous bound relative to the requested timeout while separating scheduler delay from request execution, for example by testing the builder configuration or using a deterministic paused/controlled transport.
